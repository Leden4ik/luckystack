# LuckyStack

Установщик сервера хостинга на ISPConfig. Ставит nginx, PHP, MariaDB, почту, DNS,
FTP, сертификаты и саму панель, а потом остаётся на сервере и помогает его
обслуживать: обновлять, бэкапить, следить за безопасностью.

Начиналось всё с гайда HowtoForge «The Perfect Server», по которому я руками
собирал серверы. Руками долго, и каждый раз что-то забываешь, поэтому гайд
превратился в пошаговый мастер. Потом к нему обросли дополнения, без которых мне
уже неудобно жить: панель обслуживания прямо в ISPConfig, уведомления в Telegram,
CrowdSec, бэкапы с восстановлением из панели и так далее.

Документация с примерами: https://luckystack.luckyman.name

## Что ставится

- nginx, собранный из исходников: HTTP/3, Brotli и zstd, свежий OpenSSL. Профиль
  сборки выбирается в мастере, можно отметить модули вручную.
- PHP нескольких версий сразу (7.4–8.5 из репозитория Sury), FPM и OPcache.
- MariaDB из официального репозитория или из пакетов системы, Redis по желанию.
- Почта: Postfix, Dovecot, Rspamd, ClamAV, Roundcube.
- DNS на BIND, FTP на PureFTPd с квотами.
- Сертификаты Let's Encrypt, в том числе настоящий сертификат для имени самого
  сервера (панель и почта).
- Защита: CrowdSec или UFW, fail2ban, проверка на вредоносные файлы.
- Monit, Node.js, phpMyAdmin, PostgreSQL с pgAdmin по желанию.
- ISPConfig, по умолчанию свежая сборка ветки разработки, можно выбрать stable.

Всё, кроме основы, включается галочками в мастере.

Apache в мастере пока скрыт. С ним ставится только база, без дополнений, поэтому
полноценную поддержку Apache добавлю следующим выпуском.

## Что сверху

- Панель обслуживания в ISPConfig: обновления по пунктам, бэкап перед обновлением
  ядра, откат nginx и Roundcube, проверка здоровья сервера, кнопки для исправления
  найденных проблем.
- Уведомления на почту и в Telegram. Из бота можно разрешить IP (`/allow`)
  и посмотреть, где он забанен (`/check`).
- Панели CrowdSec и fail2ban: кто забанен, снять бан, список доверенных IP.
- Бэкапы по таймеру и восстановление из панели.
- Заморозка vhost: правки в конфиге сайта не пропадают, когда ISPConfig его
  перегенерирует.
- Автотюнинг MariaDB, PHP и Postfix под память сервера.

## Требования

- Чистый Debian 12 или 13, Ubuntu 22.04 или новее.
- root.
- От 2 ГБ памяти (nginx собирается на месте) и пара гигабайт на диске.
- Имя сервера вида `server1.example.com`, лучше сразу с A-записью.

Ставить на сервер, где уже что-то крутится, не стоит. Установщик это заметит
и предложит безопасные варианты, но рассчитан он на чистую систему.

## Как поставить

```bash
curl -L https://github.com/Leden4ik/luckystack/archive/refs/heads/main.tar.gz | tar xz
cd luckystack-main
sudo ./server-setup.sh
```

Откроется меню, дальше мастер спросит всё по порядку. Сначала установщик
копирует себя в `/opt/luckystack` и дальше работает уже оттуда.

Если хочется сначала посмотреть, что он будет делать, есть демо-прогон,
который ничего не меняет:

```bash
sudo ./server-setup.sh --dry-run
```

Сборка nginx и первая загрузка баз ClamAV идут долго, это нормально.
Что происходит, видно в журнале: `tail -f /var/log/luckystack/setup.log`.

## Как пользоваться потом

После установки всё делается командой `luckyctl`. Просто `luckyctl` открывает
то же меню, а для частых дел есть команды:

```bash
luckyctl status                # что стоит и каких версий
luckyctl check                 # проверка здоровья сервера
luckyctl update                # обновить пакеты и заново наложить наши настройки
luckyctl update nginx          # пересобрать nginx на свежую версию
luckyctl rollback nginx        # вернуть прошлую сборку nginx
luckyctl backup                # сделать бэкап сейчас
luckyctl add-php 8.4           # доставить версию PHP
luckyctl log                   # хвост журнала
luckyctl help                  # все команды
```

Большую часть того же можно сделать из панели ISPConfig, в меню «Дополнения».

## Где что лежит

```
/opt/luckystack/current          код рабочего выпуска (прошлые рядом, для отката)
/etc/luckystack/setup.conf       ответы мастера и пароли, только для root
/var/lib/luckystack/setup.state  какие этапы пройдены
/var/log/luckystack/setup.log    журнал
```

В `setup.conf` лежат сгенерированные пароли, его никуда не выкладывайте.

После установки на экране будут все доступы. Пароль `admin` от панели ISPConfig
смените сразу.

## Если что-то пошло не так

Если этап упал, установщик покажет последние строки журнала и предложит повторить,
пропустить или выйти. Продолжить потом можно с того же места: `luckyctl install --resume`.

Если сборка nginx падает раз за разом, помогает чистая сборка без остатков
прошлых попыток: `luckyctl install --clean-build --only webserver`.

Подробно про все ключи, этапы и настройки написано в
[DOCUMENTATION.md](DOCUMENTATION.md), про первые шаги после установки в
[GETTING-STARTED.md](GETTING-STARTED.md).

## Важно

Скрипт ставит пакеты и меняет системные настройки: fstab, firewall, systemd,
конфиги служб. Перед боевым сервером лучше прогнать его на тестовом.
