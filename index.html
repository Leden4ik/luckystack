LuckyStack

Готовый веб- и почтовый сервер на nginx, PHP и ISPConfig. Ставится мастером на чистый Debian или Ubuntu, дальше обслуживается из панели или командой luckyctl.

Установка на чистый сервер, от root 
curl -L https://github.com/Leden4ik/luckystack/archive/refs/heads/main.tar.gz | tar xz
cd luckystack-main
bash server-setup.sh

Исходный код и выпуски: github.com/Leden4ik/luckystack

ISPConfig хорошая панель, но после её установки сервер ещё далёк от готового. nginx из пакетов без HTTP/3 и Brotli, почта принимает пароли открытым текстом, firewall не настроен, бэкапа нет, а обновление панели затирает ручные правки. LuckyStack закрывает всё это: собирает nginx, ставит PHP нескольких версий, почту с антиспамом, защиту, бэкапы и уведомления, а в ISPConfig добавляет группу пунктов меню Дополнения, из которой всё это видно и можно обслуживать.

Я делал его для своих серверов и обкатываю на них же. Каждое изменение сначала проходит тестовый сервер и только потом попадает на рабочий.

Мастер с умолчаниями

Можно пройти одним Enter: имя сервера, порт SSH и профиль подставляются сами. Сбой на этапе не губит установку, её можно продолжить.

Панель вместо SSH

Версии, проверки, обновление, откат, бэкапы, баны и уведомления в ISPConfig.

Обновления без страха

Перед ядром бэкап, после ядра наши правки накладываются заново, nginx и вебмейл откатываются одной командой.

Быстрый старт

От пустого сервера до работающей панели. Дольше всего идёт сборка nginx, остальное ставится из пакетов.

  1. Подготовьте имя сервера

    Выберите полное имя, например server.example.com, и создайте у регистратора A-запись на IP сервера. По этому имени будет открываться панель, на него выпускается сертификат и с него уходит почта. Проверить, что запись уже работает:

    # на своём компьютере
dig +short server.example.com
203.0.113.10
  2. Зайдите на сервер по SSH ключом

    Мастер предложит закрыть вход по паролю, поэтому ключ лучше положить заранее. Если ключа нет, создайте его командой ssh-keygen -t ed25519 и передайте на сервер через ssh-copy-id root@203.0.113.10.

  3. Запустите установку 
    curl -L https://github.com/Leden4ik/luckystack/archive/refs/heads/main.tar.gz | tar xz
cd luckystack-main
bash server-setup.sh

    Команды скачивают код с GitHub и запускают мастер. Перед этим его можно спокойно прочитать: это обычные bash-скрипты. При первом запуске установщик копирует себя в /opt/luckystack, ставит команду luckyctl и дальше работает уже оттуда, скачанную папку можно удалить.

  4. Ответьте на вопросы мастера

    Почти везде можно просто нажимать Enter, значение по умолчанию подходит большинству. Подробно про каждый вопрос в разделе Мастер установки.

  5. Откройте панель

    В конце мастер покажет адрес панели и пароль администратора, а копию доступов положит в /root/server-access.txt. Панель открывается по имени сервера, порт выбирается в мастере, по умолчанию 8080:

    https://server.example.com:8080

    Если вы меняли SSH или включили firewall, мастер попросит подтвердить, что доступ к серверу не потерян: откройте второе окно, зайдите по SSH и выполните touch /run/luckystack-net-ok. Без подтверждения через 5 минут SSH и firewall сами вернутся к прежним настройкам.

    Первым делом включите двухфакторный вход для admin и проверьте раздел Дополнения: там видно, что сервер в порядке.

  6. Проверьте сервер 
    luckyctl check

    Должно получиться без ошибок. Предупреждения нормальны для свежего сервера, например про отсутствие копии бэкапа на другом сервере. Как выглядит вывод, показано в разделе luckyctl check.

Требования

Нужен чистый сервер: свежая установка ОС, без панелей и без сайтов. На занятый сервер мастер не пойдёт, для него есть отдельный режим подключения.

ЧтоМинимумКомментарий
ОСDebian 12 или 13, Ubuntu 22.04 или 24.04На всех четырёх проверено установкой с нуля, перезагрузкой, сайтами, почтой и восстановлением из бэкапа
Память2 ГБС ClamAV лучше 4 ГБ. На малой памяти мастер сам предложит swap или отказаться от ClamAV
Диск20 ГБПлюс место под сайты, почту и бэкапы
Сетьпубличный IPv4IPv6 подхватывается сам, если на сервере есть глобальный адрес и маршрут
Порт 25открыт у хостераНужен только если ставите почту. Многие хостеры закрывают его по умолчанию, проверьте заранее
ДоступrootЧерез sudo тоже можно
Установка

Мастер установки

Мастер задаёт вопросы по порядку, записывает ответы в файл настроек и только потом начинает ставить. До последнего подтверждения на сервере ничего не меняется.

Как выглядит вопрос

Каждый вопрос это рамка с вариантами. В квадратных скобках стоит вариант по умолчанию, он выбирается по Enter.

Итог перед установкой

После вопросов мастер сохраняет ответы в /etc/luckystack/setup.conf, показывает сводку и спрашивает, начинать ли установку. Если ответить нет, на сервере ничего не меняется: запустите luckyctl install ещё раз и поправьте нужный ответ.

Установка

Если этап упал

Мастер пишет, на каком этапе остановился, и где смотреть журнал. Исправьте причину и продолжите:

luckyctl install --resume          # продолжить с первого незавершённого этапа
luckyctl install --only php        # выполнить ровно один этап
luckyctl install --from security   # начать с этапа и идти до конца

Если сборка nginx раз за разом падает, помогает чистая сборка без остатков прошлых попыток: luckyctl install --clean-build --only webserver.

Установка

Установка без вопросов

Если серверов несколько, ответы удобно записать в файл один раз. Сначала поставьте код без мастера командой bash server-setup.sh --install-code, затем положите setup.conf в /etc/luckystack/ (права 600) и запустите установку с ключом --unattended. Всё, чего нет в файле, берётся по умолчанию, пароли генерируются и сохраняются туда же.

# /etc/luckystack/setup.conf
SERVER_FQDN='server.example.com'
TIMEZONE='Europe/Moscow'
WEBSERVER='nginx'
NGINX_CHANNEL='stable'
OPENSSL_BRANCH='3.5'
PHP_VERSIONS='8.2 8.4 8.5'
PHP_DEFAULT='8.4'
FIREWALL='crowdsec'
CROWDSEC_WITH_UFW='y'
SSH_PORT='2222'
SSH_ALLOW_IPS='198.51.100.7 198.51.100.8'
ISPCONFIG_ADMIN_IPS='198.51.100.7 198.51.100.8'
ISPCONFIG_PANEL_PORT='3333'
BACKUP_TIME='03:30'
BACKUP_RETENTION_DAYS='14'
NOTIFY_EMAIL='admin@example.org'
luckyctl install --unattended

Полный список настроек в разделе Настройки setup.conf.

Работа с сервером

Команда luckyctl

Всё, что делается с сервером из консоли, делается одной командой. Её можно вызывать из любого каталога, справка по любой подкоманде открывается через luckyctl help <команда>.

Без команды luckyctl открывает главное меню с теми же действиями.

checkПроверка здоровья: службы, порты, сертификаты, бэкапы, безопасность
log 100Последние строки журнала установщика

rollback nginxВернуть прошлую сборку nginx. Повтор отменяет откат
rollback roundcubeВернуть прошлую версию Roundcube вместе со схемой базы

luckyctl status

Показывает, что стоит на сервере. Удобно перед обновлением и когда нужно быстро ответить на вопрос, какая версия PHP по умолчанию.

Сокращено: убраны блоки со службами и админками БД.

luckyctl check

Проверяет сервер по пунктам и в конце пишет итог. ✓ значит всё хорошо, ! стоит посмотреть, ✗ что-то сломано. Та же проверка раз в шесть часов идёт в фоне, и когда появляется новая проблема, приходит уведомление.

Сокращено: из 46 пунктов показана часть. Код выхода 0, если ошибок нет, поэтому команду можно вызывать из своего мониторинга.

Работа с сервером

Панель Дополнения

Всё, что LuckyStack добавляет в ISPConfig, собрано в одной группе меню. Родные пункты ISPConfig остаются на своих местах, так что всегда видно, где своё, а где из коробки. Группа хранится в отдельном каталоге меню, поэтому обновление ISPConfig её не стирает.

Путь: System›Дополнения

Обслуживание сервера

Версии, проверки, обновление по пунктам, откат и настройки сборки nginx. Подробно ниже.

Уведомления

Почта и Telegram, какие события присылать, тихие часы, кнопка тестового сообщения.

Бэкап / Восстановление

Список снимков, бэкап по кнопке и восстановление выбранной части: базы, конфиги, сайты, почта.

Firewall IP-rules

Какие порты с каких адресов открыты. Заменяет родной Firewall ISPConfig, который умеет только открыть порт всем.

Блок-лист

Закрыть адрес или подсеть целиком, с комментарием, зачем.

Доверенные IP

Адреса, которые никогда не банятся ни CrowdSec, ни fail2ban. Свой офис, мониторинг.

CrowdSec

Кто сейчас забанен, за что и откуда, снятие бана одной кнопкой.

Fail2ban

Состояние jail'ов, список банов, разбан.

Node.js и Composer

Версии, обновление Composer, проверка зависимостей сайтов на известные уязвимости.

Заморозка vhost

Галочка в форме сайта. Ручные правки конфига nginx не пропадут, когда ISPConfig перегенерирует сайт.

Как панель меняет сервер

Сама панель ISPConfig работает не от root и ничего на сервере не меняет. Когда вы нажимаете кнопку, панель записывает задание в таблицу. В течение минуты его забирает служебный скрипт, который работает от root, и выполняет только то, что есть в его коротком списке разрешённых действий.

  • Перед запуском установщика скрипт проверяет, что его файлы принадлежат root и никто другой не может их менять. Иначе задание отклоняется.
  • Если установщик уже работает, второе задание не стартует.
  • Перед обновлением nginx или ISPConfig делается бэкап. Если он не удался, обновление не начинается.
  • Каждое задание пишет свой журнал, его видно в панели, и итог приходит в уведомлениях.

Заморозка vhost

ISPConfig хранит конфиг сайта у себя и перезаписывает файл в /etc/nginx/sites-available при каждом сохранении сайта. Если вы правили конфиг руками, правки пропадают. Галочка Не обновлять vhost в форме сайта это исправляет: после перегенерации на место кладётся ваш вариант.

Путь: Sites›Website›Options›Не обновлять vhost

Если у замороженного сайта поменять версию PHP, LuckyStack сам поправит адрес PHP-FPM в вашем конфиге, даже если сменился способ подключения с сокета на порт. Если адрес в конфиге вписан вручную и не похож на стандартный, в панели появится предупреждение, а конфиг останется как есть.

Работа с сервером

Обновления

Обновление из панели и командой luckyctl update идёт по одному пути. По умолчанию обновляются пакеты и наши настройки, ядро не трогается.

Шаг 1Бэкап

Только если выбрано ядро. Не удался бэкап, обновление не начинается.

Шаг 2Ядро

Сборка nginx, апдейтер ISPConfig. Новый nginx сначала проверяет ваш конфиг.

Шаг 3Наши правки

Всё, что затёр апдейтер ISPConfig, накладывается заново.

Шаг 4Отчёт

Итог в Telegram и на почту, журнал в панели.

Что обновляется всегда

  • Пакеты системы через apt.
  • Автообновления безопасности, sysctl, fail2ban, права на конфиги.
  • Шаблоны ISPConfig: HTTP/2, TLS 1.3 и HTTP/3 для панели и сайтов.
  • Ограничение доступа по IP: панель только по имени сервера, phpMyAdmin только со своих адресов.
  • Все панели группы Дополнения и регистрация версий PHP в ISPConfig.

Каждый пункт можно запускать сколько угодно раз. Если всё уже на месте, он так и напишет и ничего не тронет.

Ядро только по запросу

Пересборка nginx и обновление ISPConfig делаются только если вы их отметили в панели или подтвердили в консоли. Пароль root MariaDB и основные конфиги служб при обновлении не трогаются.

luckyctl update                     # спросит про каждую часть ядра
luckyctl update --dry-run           # показать план, ничего не меняя
luckyctl update nginx ispconfig     # обновить ядро без вопросов

Пример журнала обновления

Настоящий журнал задания из панели, сокращён. [→] начало шага, [✓] сделано, [i] пояснение, [!] предупреждение, [✗] ошибка.

Сбой одного шага не обрывает остальныеЕсли, например, не скачалась новая версия Roundcube, остальные шаги всё равно выполнятся, а в итоге будет написано, какой шаг не прошёл. Его можно повторить отдельно.
Работа с сервером

Откат

При каждом обновлении nginx и Roundcube прошлая версия остаётся рядом. Вернуть её можно кнопкой на вкладке Обновление или командой. Повторный откат возвращает новую версию обратно.

nginx

Прошлая сборка лежит как /usr/sbin/nginx.backup. Перед подменой она проверяет ваш текущий конфиг, и если не принимает его, откат отменяется, а nginx остаётся как был.

Roundcube

Перед обновлением вебмейла сохраняются прошлый каталог, схема и дамп его базы. Если новая версия меняла схему, при откате база возвращается из дампа. Если после отката страница входа не открывается, всё возвращается на новую версию само.

ISPConfig и базы

У ISPConfig нет второй копии рядом, поэтому перед его обновлением делается полный бэкап баз и конфигов. Вернуться можно через восстановление из снимка, сделанного перед обновлением.

Защита и данные

Безопасность

То, что обычно включают после первого взлома, здесь включено сразу. Ниже по частям, что именно и почему.

Сеть и firewall

  • ufw закрывает все порты, кроме тех, что нужны выбранным службам. SSH и панель можно открыть только для своих IP.
  • CrowdSec читает журналы nginx, SSH и почты, банит перебор паролей и сканеры и получает общий список атакующих.
  • fail2ban дополнительно следит за SSH, почтой, FTP, панелью ISPConfig, Roundcube и входом в MariaDB.
  • Адреса из списка Доверенные IP никогда не банятся, чтобы случайно не закрыть себе доступ.
  • Чтобы не потерять сервер при правке SSH или firewall, рискованные изменения откатываются сами, если за несколько минут вы не подтвердили, что доступ остался.

Доступ

  • Панель открывается только по имени сервера. Запрос по IP получает пустой ответ, так сканеры не видят, что здесь ISPConfig.
  • На 443 по IP или чужому имени соединение обрывается ещё до сертификата, так по нему не узнать, какие сайты на сервере. На 80 по IP можно выбрать: стартовая страница сервера, переадресация на его имя или пустой ответ.
  • SSH: вход только по ключу (по желанию), без проброса портов и агента, свой порт.
  • Почта и FTP принимают пароль только по TLS.

PHP и сайты

  • Версия PHP не видна в заголовках, куки сессий недоступны из JavaScript.
  • OPcache у каждого сайта свой, один сайт не может прочитать код другого из кэша.
  • Shell-пользователи ISPConfig заперты в jail, проверка в панели напоминает, если это не так.
  • Файлы сайтов с правом записи для всех находятся при проверке, исправляются кнопкой.
  • Раз в сутки сайты проверяются на вредоносный код, при находке приходит письмо.

Ядро и службы

  • sysctl: защита от подмены маршрутов, SYN-флуда, утечек адресов ядра.
  • Короткие таймауты nginx против медленных атак: заголовок 15 секунд, тело и отправка 60.
  • По желанию ограничения systemd для nginx и MariaDB: только чтение системы, отдельный /tmp, без лишних прав ядра. Оценка systemd-analyze security с ними 4.9 у nginx и 5.7 у MariaDB, чем меньше, тем лучше. Если служба с ограничениями не стартует, они снимаются сами.
  • Шифрование: TLS 1.2 и 1.3, обмен ключами X25519MLKEM768, устойчивый к квантовым компьютерам, при поддержке браузером.
Что сделать самомуВключите двухфакторный вход для всех администраторов панели: Tools›User Settings. Без него пароль от панели остаётся единственной защитой всех сайтов.
Защита и данные

Бэкапы

Каждую ночь делается снимок: дамп всех баз, /etc и конфиги ISPConfig. По желанию в снимок входят сайты и почта. Старые снимки удаляются по сроку, но последние три остаются всегда.

Сам бэкап делает скрипт /usr/local/sbin/server-backup.sh. Он работает и без LuckyStack, это удобно при восстановлении на новом сервере.

Восстановление

По умолчанию восстанавливаются только базы из последнего снимка. Остальное выбирается явно:

server-backup.sh --restore 20261107-033000 --db --etc
server-backup.sh --restore --all --yes

Восстановление перезаписывает текущие данные. Перед ним стоит сделать свежий снимок, на случай если выбрали не тот. Файлы сайтов восстанавливаются вместе с защитой, которую ISPConfig ставит на их каталоги, ничего снимать вручную не нужно.

ГотовитсяКопия на второй сервер в режиме только добавления: сервер может дописывать новые снимки, но не может удалить или переписать старые. Тогда даже взломанный сервер не уничтожит свои бэкапы.

Решение проблем

Установка остановилась на одном из этапов

Посмотрите последние строки журнала, там будет строка с [✗] и причина:

grep -n '\[✗\]' /var/log/luckystack/setup.log | tail -5

Частые причины: не скачался архив с исходниками (сеть или зеркало), кончилась память при сборке, у хостера закрыт порт 25. После исправления запустите luckyctl install --resume, пройденные этапы повторяться не будут.

Панель не открывается

Проверьте три вещи по порядку:

  • Вы заходите по имени сервера, а не по IP. По IP панель ничего не отдаёт.
  • Ваш текущий IP есть в списке доступа. Если адрес сменился, добавьте его в панели Firewall IP-rules с другого адреса из списка, или с сервера: ufw allow from 203.0.113.5 to any port 8080 proto tcp (порт ваш, из мастера).
  • Адрес не забанен: cscli decisions list | grep 203.0.113.5. Снять бан: cscli decisions delete --ip 203.0.113.5.
После обновления nginx сайты не открываются

Сначала проверьте конфиг командой nginx -t. Если ошибка в конфиге, она будет в выводе. Если конфиг в порядке, а проблема в новой сборке, верните прошлую: luckyctl rollback nginx. Откат занимает секунды и сам проверяет, что прошлая сборка принимает ваш конфиг.

В панели задание пишет «установщик уже запущен»

Значит, обновление уже идёт: из консоли или другим заданием. Дождитесь окончания. Если вы уверены, что ничего не идёт, проверьте cat /run/luckystack-update.pid и есть ли такой процесс. После перезагрузки этот файл исчезает сам.

Задание пишет «небезопасные права или владелец»

Панель отказывается запускать установщик, если его файлы может менять кто-то кроме root. Обычно это следствие копирования через FTP или распаковки не от root. Исправить:

chown -R root:root /opt/luckystack
chmod -R go-w /opt/luckystack
Не приходят уведомления

Нажмите Тест на странице Уведомления. Если в Telegram пришло, а на почту нет, загляните в очередь почты mailq и в папку Спам. Для доставки на внешние ящики у домена отправителя должны быть DKIM и SPF, их можно включить в ISPConfig у почтового домена.

Вопросы

Можно поставить на сервер, где уже есть сайты?

Мастер рассчитан на чистый сервер и остановится, если найдёт рабочую установку. Для сервера, собранного вручную по гайду Perfect Server, есть luckyctl adopt: сначала бэкап, потом подтверждение, и ставятся только бэкап, уведомления и защита. Ваш nginx, шаблоны и конфиги ISPConfig не трогаются.

Почему nginx собирается из исходников?

Пакетный nginx в Debian идёт без HTTP/3 и Brotli и со старым OpenSSL. Сборка даёт свежий nginx, OpenSSL с долгой поддержкой и только нужные модули. Обновлять её не сложнее, чем пакет: одна галочка в панели, а прошлая сборка остаётся для отката.

Обновление ISPConfig не сотрёт ваши правки?

Апдейтер ISPConfig действительно перезаписывает часть файлов. Поэтому после него LuckyStack заново накладывает свои правки, а меню Дополнения лежит в отдельном каталоге, который апдейтер не трогает.

Чем это отличается от ISPConfig Autoinstaller?

Autoinstaller ставит ISPConfig и пакеты из репозиториев, дальше сервер ваш. LuckyStack ставит сборку nginx, защиту и бэкапы, а главное остаётся с сервером дальше: обновляет, откатывает, проверяет и сообщает о проблемах.

Где хранятся пароли?

В setup.conf с доступом только для root. В журналы пароли не пишутся, при записи они маскируются.

Можно ли удалить LuckyStack и оставить сервер?

Да. Все службы обычные: nginx, PHP-FPM, MariaDB, ISPConfig. Если удалить LuckyStack, сервер продолжит работать, пропадут только наши панели, бэкап по расписанию и уведомления.

Что дальше

Первый выпуск вышел: команда luckyctl, раскладка по /opt, /etc и /var, проверка на Debian 12 и 13, Ubuntu 22.04 и 24.04. Следом:

  • Полноценный Apache: те же защита, тюнинг и дополнения, что у nginx.
  • Установка одной командой через get.sh и подписанные выпуски, чтобы установка и self-update проверяли, что скачано именно то.
  • Копия бэкапов на второй сервер, которую нельзя удалить с основного.
