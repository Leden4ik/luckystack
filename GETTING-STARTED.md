# Первые шаги после установки

Сервер установлен — что дальше? Этот гайд для обычного пользователя: как войти в панель,
завести первый сайт и почтовый ящик, настроить DNS и не наступить на частые грабли.

> Все доступы (URL, логин, где пароли) сохранены в **`/root/server-access.txt`** (chmod 600).
> Проверить здоровье сервера в любой момент: `luckyctl check`.

---

## 1. Вход в панель ISPConfig

1. Открой `https://ВАШ-FQDN:8080` (порт мог быть изменён — точный в `server-access.txt`).
   - Если домен ещё не указывает на сервер — временно по `https://IP:порт` (будет предупреждение
     о самоподписанном серте, это нормально до выпуска Let's Encrypt).
2. Логин `admin`, пароль — из `server-access.txt` (`ISPCONFIG_ADMIN_PW`).
3. **Сразу включи 2FA**: вверху → твой профиль → *Two Factor Authentication* (TOTP, приложение
   Google Authenticator/Aegis). Это лучшая защита панели от подбора пароля.
4. Смени пароль admin на свой: *Tools → Password and Language*.

ISPConfig — это «пульт»: через него заводятся сайты, почта, БД, FTP, DNS. Руками в конфигах
лазить не нужно — панель всё генерирует сама.

---

## 2. Направь домен на сервер (DNS)

Прежде чем заработает сайт и SSL — домен должен указывать на IP сервера. У регистратора/DNS-хостинга:

| Запись | Имя | Значение |
|---|---|---|
| **A** | `@` и `www` (и нужные поддомены) | IP вашего сервера |
| **A** | FQDN сервера (напр. `server1.example.com`) | IP сервера |

Проверка: `ping ваш-домен` должен показать IP сервера. Распространение DNS — до нескольких часов.

> Let's Encrypt-сертификат выпустится автоматически, только когда **A-запись указывает на сервер**
> и открыт порт 80. Иначе сайт останется на самоподписанном серте — это поправимо позже.

---

## 3. Первый сайт

1. *Sites → Website → Add new website*.
2. Заполни: **Domain** (например `example.com`), при необходимости — лимиты (по умолчанию ок).
3. **PHP**: выбери версию (доступны все установленные) и режим (PHP-FPM — рекомендуется).
4. Поставь галку **SSL** и **Let's Encrypt** — серт выпустится сам (нужен п.2: домен на сервер + :80).
5. Сохрани. Через минуту сайт доступен по `https://example.com`.

Файлы сайта лежат в `/var/www/example.com/web/`. Заливать — через FTP/SFTP (п.5) или из панели.

---

## 4. База данных для сайта

*Sites → Database → Add new database*. Панель создаст БД и пользователя — данные подключения
покажет там же. Веб-доступ к БД: **phpMyAdmin** (`http://ВАШ-FQDN/phpmyadmin`) или Adminer
(точный URL — в `server-access.txt`).

---

## 5. FTP/SFTP для загрузки файлов

*Sites → FTP-User → Add new FTP-User* — привяжи к сайту, задай логин/пароль. Подключайся
FileZilla/WinSCP по **SFTP** (порт SSH сервера) или FTP (если ставился компонент FTP).

---

## 6. Почта

1. *Email → Domain → Add new domain* — добавь почтовый домен (например `example.com`).
2. *Email → Email Mailbox → Add new mailbox* — заведи ящик (`you@example.com` + пароль).
3. **Опубликуй DNS-записи почты** — они подготовлены в **`/root/mail-dns-records.txt`**
   (MX, SPF, DKIM, DMARC). Без них письма будут попадать в спам или не уходить.
4. **PTR (обратная зона)** для IP сервера настраивается **у хостера** (в панели VPS), не у
   регистратора домена. Тоже важна для доставляемости.
5. Вход в почту: **Roundcube** `https://ВАШ-FQDN/roundcube` — логин = адрес ящика, пароль ящика.
   Пользователь сам может менять пароль/автоответчик/фильтры/пересылку (если ставился `rcplugins`).

> ⚠️ Многие хостеры **блокируют исходящие порты 25/465/587** на VPS. Проверить с сервера:
> главное меню установщика → «Проверка блокировки почтовых портов». Если заблокировано —
> запросить разблокировку у хостера (отчёт сохранится в файл для приложения к тикету).

---

## 7. Резервные копии

- Бэкап БД + конфигов идёт **ежедневно** автоматически (если ставился компонент backup).
- Список снимков: `/usr/local/sbin/server-backup.sh --list`
- Бэкап вручную прямо сейчас: `/usr/local/sbin/server-backup.sh`
- **Восстановление**: `luckyctl restore` (интерактивно, с выбором снимка и что вернуть).
- Если настроена оффсайт-копия (`BACKUP_REMOTE_*`) — снимки дублируются вне сервера.

---

## 8. Обслуживание (полезные команды)

| Команда | Зачем |
|---|---|
| `luckyctl check` | Все сервисы/порты/TLS/диск — зелёный/красный |
| `luckyctl status` | Что установлено и какие версии |
| `luckyctl diagnostics` | Собрать архив для поддержки (пароли вырезаны) |
| `luckyctl update` | Обновить пакеты + переприменить улучшения (не трогая ядро) |

---

## 9. Чек-лист безопасности

- [ ] Включена **2FA** в панели (п.1).
- [ ] Сменён пароль `admin`.
- [ ] Вход по **SSH-ключу** настроен (см. `DOCUMENTATION.md` → «SSH-доступ и авторизация»).
- [ ] Firewall активен: `luckyctl check` (или `ufw status`).
- [ ] Настроены **уведомления** (`NOTIFY_*`) — узнаешь о проблемах заранее.
- [ ] `server-access.txt` сохранён в надёжном месте и удалён лишний доступ к серверу.

---

## Частые вопросы

- **Сайт/SSL не открывается по домену** → проверь, что A-запись указывает на сервер (п.2) и
  прошло время на распространение DNS; для SSL нужен открытый порт 80.
- **Панель пускает по IP, хотя включён «только по FQDN»** → серт ещё не выпущен (запрет ставится
  вместе с LE). Повторить: `luckyctl install --only hostcert`.
- **Письма не уходят** → порты 25/465/587 заблокированы хостером (п.6) или не опубликованы
  DNS-записи почты (`/root/mail-dns-records.txt`).
- **Забыл пароль** → все пароли в `/root/server-access.txt` и `/etc/luckystack/setup.conf` (только root).
